SKU:`yuncode6469300002` = 免费试用(50 次 / 30 天);付费档位 2 元/100 次起。

## 接口

| 项 | 值 |
|----|-----|
| 网关域名 | `jtidcard.market.alicloudapi.com` |
| 路径 | `/idcardcheck`(**全小写无分隔**,不是 camelCase) |
| 方法 | `GET` |
| 认证 | Header `Authorization: APPCODE <AppCode>`(也支持 AppKey&AppSecret 签名) |
| 返回 | JSON |

```
GET https://jtidcard.market.alicloudapi.com/idcardcheck?name=<姓名>&idcard=<18位证号>
Authorization: APPCODE <AppCode>
```

参数(全在 Query,无 body / 无额外 header):

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | Y | 姓名 |
| `idcard` | Y | 身份证号 |

## 成功响应

```json
{
  "msg": "成功",
  "success": true,
  "code": 200,
  "data": {
    "result": 1,
    "order_no": "626072002058391552",
    "desc": "不一致",
    "sex": "男",
    "birthday": "19940320",
    "address": "江西省南昌市东湖区"
  }
}
```

- `data.result`:**0 一致 / 1 不一致 / 2 无记录(预留)**
- ⚠️ **`result=1`(不一致)时仍会返回该证号对应的 sex/birthday/address** —— 这是「用你的名字去查别人信息」的口子。服务端**不要**把这些字段透给调用方或落库。

## 失败响应

```json
{"msg": "身份证不合法", "success": false, "code": 400, "data": null}
```

实测:`idcard=11010119900307123X`(校验位错)→ `身份证不合法`;`idcard=123456` → `身份证号长度不合法`;缺参数 → 空响应体。

| code | 错误信息 |
|------|----------|
| 400 | 参数错误 |

| 1001 | 其他,以实际返回为准 |
| 1002 | 查询失败(号段不支持;调用超限) |
| 1003 | 查无记录 |

`1002` 同时涵盖**号段不支持**和**调用超限**——别把两种都当成「用户输入错」。

## 本地预校验(省配额的关键)

发上游前先在服务端拦掉,可省掉大部分无效调用:

1. `^\d{17}[0-9X]$`,统一大写(末位 `x` → `X`)
2. 省级码 11–82
3. 出生日期真实且 ≤ 今天
4. **GB 11643 校验位**:权重 `[7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2]`,校验码表 `10X98765432`,`sum(前17位 × 权重) % 11` 取表
5. 姓名:2–20 字符,首字符中文或字母;过滤控制符/零宽/双向控制符

客户端(iOS/Swift)也做一份同样规则,可即时反馈并进一步省配额——注意**两侧规则必须一致**,否则会出现「客户端放行、服务端拒」的困惑。

## 隐私处理(本项目的约定)

- 落库:掩码姓名(`张*三` / 两人名 `张*`)+ 证号掩码(前 4 + 12 个 `*` + 后 2)+ `HMAC-SHA256(证号, 服务端 pepper)`
- **绝不明文存证件号**;日志只记结果码
- 未强制「一证一号」唯一约束(可查重但未拦),需要时按 HMAC 指纹加唯一索引

## 实测结论(2026-10 接入验证)

| 场景 | 结果 |
|------|------|
| 位数非法证号 | `400 bad_idcard`,**不耗配额** |
| 校验位错误 | `400 bad_idcard`,**不耗配额** |
| 非法姓名(单字) | `400 bad_name` |
| 格式合法但非真人 | 上游返回 `result=1` → 本地 `mismatch`,**不置为已认证** |
