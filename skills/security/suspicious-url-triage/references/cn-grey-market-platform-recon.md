# 国内「卡密／接码／代充」黑灰产平台 — 特征词与实战案例

用于快速判定一个「充值／兑换／验证」页背后到底是什么业务。

## 1. 业务链词汇表（看到这些词基本可以定性）

| 词 | 含义 |
|---|---|
| 卡密 / 发卡 | 一串凭据作为商品，链接里常是 `c=` `code=` |
| 接码 / 二次接码 | 拦截/复用他人短信验证码 |
| 换绑验证 | 把账号绑定的手机号改成攻击者的 |
| 登录验证 | 用拦截到的验证码登录他人账号 |
| 号码管理 / 库存面板 | 手机号池（批量注册/接码用） |
| 代付工作台 | 替他人下单付款 |
| 代理管理 / 云码共享联盟 | 分销体系，向下游代理发卡 |
| 开主号 / 用户配额 / 团队管理 | 批量注册平台账号（如剪映团队号） |
| 扫码登录 / 授权（安卓端/苹果端/电脑端） | 诱导扫码授权，接管会话 |
| 续期管理 | 会员续费/续期 |

配套的「掩护站」很常见：留言板、暖心驿站、导航站等无业务页面挂在同一主域下。

## 2. 页面级信号

- 单页 PHP + 服务端渲染，无 API，`?c=<16位十六进制>` 这类不透明 token。
- 页脚固定话术：「信息仅用于本次充值验证」「安全通道」「X 仅用于本次登录和换绑验证」。
- 状态靠内联 JS 常量区分：`const isSuccess/isError/step/waiting`。
- 后台入口常在同域根路径 `/`、`/index.php`：账号 + 密码 + **Google Authenticator 6 位动态码**。
- 报错文案会暴露人工客服流程，如「验证码异常，请截图发给客服」「后台未点发送前，验证码无法填写」。
- 兄弟子域直接命名业务：`zuoyebang.`（作业帮）、`lxz.`（剪映）、`cc.`（迅雷）等。

## 3. 实战案例：`chongzhi.100lai.com/recharge.php?c=DAD53A07D9D32D2D`（2026-10）

用户丢来链接要求「解析全部」。结论链条：

1. **页面**：单页「充值服务中心」，URL 的 `c` 就是卡密。
2. **状态机（实测）**：
   - 原值 → `✅ 充值成功 手机号：13302744100`（该卡已被此号核销，手机号对任何持链接者公开 = 隐私泄露）
   - 随机/近似值（`AAAA…`、`0000…`、只差一位）→ `卡密不存在`
   - 缺失/空 → 也返回「成功 手机号：13860639701」（服务端默认行，**不可当作真实状态**）
   - 大小写不敏感；`step/phone/reset` 等参数无效；对已用卡 POST 手机号不改状态。
3. **归属**：`100lai.com` 根域 → `/home/user/index.html`「幽梦网络科技-用户登录」会员中心，页脚自称 `鄂ICP备2021006744号-4`；域名 2014 年注册、阿里云注册商 + 阿里云 DNS；公开检索同名主体是广州公司，**备案省份对不上、无法核实**。
4. **网络**：CNAME → `a1100460.zh2cdn2.ddosjq.xyz` → `211.154.24.182`（湖北武汉，AS146817 湖北飞迅网络）；`Server: huyuncdn/3.5`，HEAD 被 WAF 403；HTTPS 证书 `CN=mbackadmin.kfdl.oreo20.cn` 与域名完全不匹配（共享节点乱挂证书）。
5. **子域枚举（决定性证据）**：certspotter 查出 12 个子域，逐个抓 title：
   - `zuoyebang.100lai.com` → 「作业帮后台登录」/「作业帮验证中心」，页面含手机号表单 + **登录验证码** + **换绑验证码** 两套表单，文案「**二次接码**｜登录验证｜换绑验证」「后台未点发送前，验证码无法填写」
   - `cc.100lai.com` → 「迅雷扫码系统」Vue+Element 后台：卡密管理/卡密验证/**号码管理**/库存面板/续期管理/代理管理/**代付工作台**/**云码共享联盟**/微博·苹果·电脑端扫码登录
   - `lxz.100lai.com` → 「LXZ剪映团队系统」：卡密列表/团队管理/**开主号**/用户配额/远程日志
   - `ceshi.` 扫码登录系统；`myc.` 留言板（掩护页）；另有 `sm9/vip/plus/zu/baidu/bd5`
6. **定性**：一个面向黑灰产的「低价代充 + 接码/换绑 + 卡密分销」平台，覆盖百度网盘、作业帮、剪映、迅雷等。
7. **风险告知**：卡密链接即凭据；页面索要的手机号+验证码极可能是用户自己账号的登录码/换绑码（交出=盗号）；无有效 HTTPS 证书；卡密已被他人核销（典型「已用卡密」骗局）。

## 4. 可直接复用的命令

```bash
# 1) 拉页（HEAD 常被 WAF 403，用 GET + 移动端 UA）
curl -sS -m 25 -A "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 Version/17.0 Mobile/15E148 Safari/604.1" \
  "http://HOST/recharge.php?c=TOKEN" -o page.html

# 2) CNAME / CDN / IP 归属
dig +noall +answer HOST
curl -sS "https://ipinfo.io/<IP>/json"

# 3) TLS 证书（错配 = 共享节点；SAN 可能泄露运营方其它域名）
echo | openssl s_client -connect HOST:443 -servername HOST 2>/dev/null | openssl x509 -noout -subject -ext subjectAltName

# 4) 子域枚举 + 逐个抓 title（脚本在 ../scripts/ct_subdomains.py）

# 5) SPA 入口 JS（必须 -L，301 会让文件为空）
curl -sSL -m 40 -A "Mozilla/5.0" "http://HOST/assets/index-XXXX.js" -o app.js
# 再 grep 中文字符串与 "/route" 字符串
```

## 5. 判定速查

- 只有主站看不出问题 → **一定要枚举子域**，兄弟站的标题就是答案。
- 有后台登录 + 动态口令 + 卡密体系 + 代理体系 → 商业化成规模的黑灰产平台，不是单点骗子。
- 证书错配 / 自建 ddos 类 CDN / 备案主体对不上 → 不要相信页面上的任何「安全」话术。
